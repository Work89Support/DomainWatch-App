# KPI ขาดการติดต่อของเครื่องซิม

- เริ่มเก็บหลักฐานจาก heartbeat ที่ server รับหลังติดตั้งรุ่นนี้ ไม่มีการเดาช่วงย้อนหลังจาก lastSeenAt หรือ MobileCheckLog (เก็บเฉพาะสถานะ URL เปลี่ยน)
- หลัง heartbeat ล่าสุด 12 นาที จึงเริ่มนับขาดการติดต่อ จบเมื่อ server รับ heartbeat ใหม่หรือปิด/ลบเครื่อง
- เปิดใช้งานหรือผูกเครื่องใหม่เริ่ม baseline ใหม่ ไม่คิดช่วงที่ปิดใช้งาน
- เก็บ snapshot ผู้ดูแล ณ เวลานั้น เปลี่ยนผู้ดูแลแบ่งช่วง ไม่ย้าย KPI ย้อนหลัง
- กรองตามช่วงเวลาที่ทับกับวันที่เลือก (Asia/Bangkok) ไม่ยึดวันเริ่มเคส ไม่มีหลักฐานไม่เท่ากับไม่เคยออฟไลน์
- แสดงเวลาออฟไลน์ และส่วนทับกับช่วง adminUpdatedAt ถึง resolvedAt ของเคสเครื่องเดียวกันที่ไม่ PAUSED; รวมช่วงซ้อนของหลายเคสเพียงครั้งเดียวต่อเครื่อง
- ผลทับช่วงรอรีเช็คเป็นความสัมพันธ์ตามเวลา ไม่ยืนยันสาเหตุหรือความผิดของพนักงาน ไม่เพิ่มเวลาเข้า KPI งานแอดมิน
- หลายเครื่องรวมเป็นนาที-เครื่อง ไม่ใช่เวลาทำงานของคน; ยังไม่มี Telegram push สำหรับออฟไลน์ หน้ารายงานคำนวณ ณ เวลาโหลด/รีเฟรช
- ประวัติ AgentPresence ไม่ลบตามเครื่อง ไม่เก็บ token/IP/ตำแหน่ง เก็บ HEARTBEAT / OWNER / STOP เรียงตามเวลาจาก server
- ก่อน deploy: prisma generate, tsc --noEmit --incremental false, npm test. Production build เพิ่มตารางผ่าน db push เดิม ห้าม accept-data-loss
