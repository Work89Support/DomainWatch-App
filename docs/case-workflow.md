# การรับเรื่อง ปิดเคส และประวัติย้อนหลัง

เปิด **เหตุการณ์** แล้วเลือกแหล่งตรวจ ระบบกลางหรือเครือข่ายซิม

1. กด **รับเคสนี้** ระบบบันทึกชื่อผู้รับและเวลาจริง รับพร้อมกันได้เพียงคนเดียวต่อหน้าที่ เวลารับเรื่องครั้งแรกจะไม่ถูกเขียนทับเมื่อแก้ลิงก์
2. กด **ประวัติ / บันทึก / ส่งต่อ** เพื่อบันทึกสิ่งที่ตรวจพบ หรือระบุชื่อผู้รับผิดชอบที่ส่งต่อและเหตุผล การกดส่งต่อเก็บบันทึกในระบบ ผู้ส่งยังต้องติดต่อผู้รับโดยตรง
3. แก้ไขลิงก์ตามปกติ ประวัติเก็บ URL ก่อน/หลังและชื่อผู้แก้ การแก้ผ่าน Master Data จะปรากฏในเคสที่ยังเปิดอยู่ด้วย
4. เคสระบบกลาง: บันทึกลิงก์ใหม่เมื่อผลตรวจผ่าน หรือกรอกเหตุผลแล้วกด **ตรวจซ้ำและปิดเคส** ถ้าตรวจไม่ผ่านจะปิดไม่ได้ ผล HTTP ยืนยันการเข้าถึงเท่านั้น ผู้รับผิดชอบยังต้องตรวจว่าเป็นเว็บและหน้าที่ถูกต้อง
5. เคสซิม: หลังบันทึกเป็น **ปรับแก้แล้ว · รอตรวจยืนยัน** รอเครื่องซิมตรวจตามเกณฑ์เดิม ระบบบันทึกเหตุผลปิดจากลิงก์หลักหรือสำรอง
6. การพักเฝ้าดูเป็น **พักการเฝ้าดู** เก็บประวัติ แต่ไม่ใช่ผลแก้สำเร็จ

กด **ค้นประวัติการดำเนินการย้อนหลัง** เพื่อกรองชื่อคน บริษัท เลขเคส แหล่งตรวจ และช่วงวันที่ หน้านี้นับเป็นรายการดำเนินการ หนึ่งเคสอาจมีหลายรายการ ใช้เวลาประเทศไทย ประวัติที่บันทึกแล้วไม่มีปุ่มแก้ไขหรือลบและไม่ถูกลบตาม Master Data หรือเครื่องตรวจ

KPI เพิ่มจำนวนเคสที่มีเวลารับเรื่อง เวลาตรวจพบถึงรับเรื่อง และเวลาตรวจพบถึงปิดเคส เวลาปิดรวมเวลารอเครื่องตรวจยืนยันด้วย จึงไม่ใช่เวลาทำงานของพนักงานทั้งหมด เคสที่ไม่มีหลักฐานระบุผู้ทำรายการจะไม่นำไปเดาผลงานให้บุคคลใด

ผู้บริหารอ่านเคสและค้นประวัติได้ แต่รับเรื่อง แก้ไข หรือปิดเคสไม่ได้

## การเปิดใช้

การ build บน Vercel จะเพิ่มตารางประวัติและคอลัมน์เวลารับเรื่องแบบไม่ยอมรับการสูญหายของข้อมูล แล้วเรียก `scripts/backfill-case-history.ts` เพื่อเก็บสำเนาเคสเก่าที่มีอยู่ก่อนเปิดใช้งาน รันซ้ำได้โดยไม่สร้างรายการซ้ำ ข้อมูลที่ถูกลบไปก่อนหน้านี้ไม่สามารถกู้คืนจากสคริปต์นี้ได้

ข้อมูลย้อนหลังเป็นสำเนาค่าที่เหลืออยู่ ณ วันเปิดใช้ ไม่ใช่หลักฐานว่า URL นั้นเป็นค่าในวันเกิดเหตุ ส่วนประวัติใหม่จะเก็บข้อมูลขณะทำรายการจริง
